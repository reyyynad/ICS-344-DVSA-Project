Lesson 7 — Over-Privileged Function

Target  : DVSA-SEND-RECEIPT-EMAIL Lambda's execution role. Ships with
          AmazonSESFullAccess (managed) plus one or more wildcard inline
          policies (Resource:"*") for S3 and DynamoDB.
Primitive: the Lambda only needs ses:SendRawEmail + read-one-receipt
           from S3. Any compromise of it (e.g. via Lesson 1's RCE) can
           abuse the attached role to read any bucket / scan any table.
Proof   : IAM Policy Simulator API says these unrelated actions are
          ALLOWED. After fix.py --apply, the same actions are DENIED.

Scripts : lessons/lesson7/payload.json — least-privilege replacement policy
          lessons/lesson7/exploit.py   — simulate_principal_policy calls
          lessons/lesson7/run.sh       — wrapper
          lessons/lesson7/fix.py       — attaches payload.json to the role

Env vars: ROLE_ARN    = arn:aws:iam::<ACCOUNT_ID>:role/DVSA-SEND-RECEIPT-EMAIL-Role
          ROLE_NAME   = DVSA-SEND-RECEIPT-EMAIL-Role
          BUCKET      = your real DVSA receipts bucket
          ACCOUNT_ID  = your 12-digit AWS account ID

Report section: 3.7 Over-Privileged Function.
