Lesson 7 — Screenshot placement & captions
==========================================

Save every image in this folder (screenshots/Lesson7/) using the exact
filename shown. After sanitization, copy the same PNG into loot/lesson7/.

REDACT in every screenshot: your 12-digit AWS account ID (it appears in
role ARNs, Policy Simulator URLs, and CloudTrail breadcrumbs).

--------------------------------------------------------------------
01-iam-role-permissions.png      [REQUIRED]
--------------------------------------------------------------------
How to capture:
  AWS Console → IAM → Roles → DVSA-SEND-RECEIPT-EMAIL-Role →
    "Permissions" tab.
  Expand the inline policies and show the list of attached managed
  policies (AmazonSESFullAccess must be visible).

Must be visible:
  - Role name in breadcrumb
  - "AmazonSESFullAccess" (managed)
  - At least one inline policy with "Resource": "*"

Caption:
  "Fig. 1 — The email-sending role carries AmazonSESFullAccess plus
   wildcard inline policies on S3 and DynamoDB, even though its only
   job is to send a receipt email."

--------------------------------------------------------------------
02-policy-simulator-s3-allowed.png   [REQUIRED]
--------------------------------------------------------------------
How to capture:
  Browse to https://policysim.aws.amazon.com/ →
  Users, groups, and roles → select DVSA-SEND-RECEIPT-EMAIL-Role →
  Select services: S3 →
  Select actions: s3:GetObject →
  Resource: arn:aws:s3:::some-random-bucket/some-key
  Click "Run Simulation".

Must be visible:
  - Role name in the left panel
  - Action s3:GetObject
  - The arbitrary resource ARN (not DVSA's own bucket)
  - Result column showing "allowed"

Caption:
  "Fig. 2 — Policy Simulator confirms the role can read ANY S3 object
   on the account, including buckets unrelated to DVSA."

--------------------------------------------------------------------
03-policy-simulator-dynamo-allowed.png   [REQUIRED]
--------------------------------------------------------------------
How to capture:
  Same Policy Simulator session, switch service to DynamoDB →
  Action: dynamodb:Scan →
  Resource: arn:aws:dynamodb:us-east-1:*:table/some-random-table.
  Run simulation.

Must be visible:
  - Action dynamodb:Scan
  - The unrelated table ARN
  - Result: "allowed"

Caption:
  "Fig. 3 — Same role can Scan any DynamoDB table on the account.
   A compromise of this Lambda is a compromise of the whole data tier."

04-exploit-py-output.png         [REQUIRED]
--------------------------------------------------------------------
How to capture:
  Terminal running:
      cd lessons/lesson7
      export ROLE_ARN="arn:aws:iam::<ACCOUNT_ID>:role/DVSA-SEND-RECEIPT-EMAIL-Role"
      python3 exploit.py
  (Redact the account ID in the ARN before capturing.)

Must be visible:
  - The script's table/list of actions
  - Several "ALLOWED (over-privileged)" rows covering S3 / DynamoDB / IAM

Caption:
  "Fig. 4 — exploit.py drives IAM:SimulatePrincipalPolicy against the
   role and marks every unrelated action it still has access to. These
   are the actions we will strip in fix.py."

05-cloudtrail-generated-policy.png   [REQUIRED]
--------------------------------------------------------------------
How to capture:
  IAM → Roles → DVSA-SEND-RECEIPT-EMAIL-Role →
  "Permissions" → "Generate policy" → range = Last 1 day → run.
  When the generated policy appears, screenshot the summary showing
  ~3 actions actually used.

Must be visible:
  - "Actions used" count (≈3)
  - The specific actions (ses:SendRawEmail, s3:GetObject on receipts,
    logs:CreateLogStream / PutLogEvents)
  - Time window

Caption:
  "Fig. 5 — CloudTrail-generated policy shows the role realistically
   needs only ~3 actions. Everything else attached to it today is
   excess blast radius."

06-after-fix-denied.png          [REQUIRED]
--------------------------------------------------------------------
How to capture:
  After running:
      export ROLE_NAME="DVSA-SEND-RECEIPT-EMAIL-Role"
      export BUCKET="your-real-dvsa-receipts-bucket"
      export ACCOUNT_ID="123456789012"
      python3 fix.py --apply
  re-open Policy Simulator and re-run the SAME s3:GetObject on the
  unrelated bucket. It should now say "denied (implicit)".

Must be visible:
  - The identical simulation to Fig. 2 but result = "denied"
  - Same role / same action / same resource

Caption:
  "Fig. 6 — After fix.py --apply installs the least-privilege policy,
   the exact same S3 read attempted in Fig. 2 is denied. The blast
   radius is now contained to DVSA's own receipts bucket."
