Lesson 2 — Screenshot placement & captions
==========================================

Save every image in this folder (screenshots/Lesson2/) using the exact
filename shown. After sanitization, copy the same PNG into loot/lesson2/.

CRITICAL SANITIZATION: every screenshot that contains a JWT must have
the middle of the token blacked out. Show only first 6 and last 6 chars.

--------------------------------------------------------------------
01-login-as-attacker.png         [REQUIRED]
--------------------------------------------------------------------
How to capture:
  Browser showing the DVSA web app after logging in with YOUR OWN
  attacker account (e.g. "attacker01"). The top nav / profile area
  should display your attacker username.

Must be visible:
  - DVSA URL bar (redact API Gateway ID)
  - The attacker username somewhere on the page
  - An empty / fresh-account cart/orders list

Caption:
  "Fig. 1 — Logged in as the attacker account. Our starting state:
   a valid Cognito session belonging to ourselves. We will upgrade this
   into impersonation of another user."

--------------------------------------------------------------------
02-devtools-idtoken.png          [REQUIRED]
--------------------------------------------------------------------
How to capture:
  DevTools → Application tab → Storage → Local Storage →
  key starting with CognitoIdentityServiceProvider....idToken.
  Click the key; copy the full token, then blur most of it for the
  screenshot.

Must be visible:
  - Local Storage panel
  - The idToken key name
  - First ~10 chars and last ~10 chars of the token (redact the middle)

Caption:
  "Fig. 2 — The attacker's idToken retrieved from Local Storage. This
   is the starter JWT that exploit.py will split, modify, and re-emit
   with the ORIGINAL signature untouched."

--------------------------------------------------------------------
03-exploit-py-forged-token.png   [REQUIRED]
--------------------------------------------------------------------
How to capture:
  Terminal running:
      cd lessons/lesson2
      python3 exploit.py --print-only
  Capture the output showing the forged token.

Must be visible:
  - Command being run
  - "Forged token:" line
  - Ideally, the decoded payload with cognito:username == victim

Caption:
  "Fig. 3 — exploit.py produces the forged JWT. The signature segment
   (3rd dot-separated block) is byte-for-byte identical to the
   attacker's token — only the payload was changed."

--------------------------------------------------------------------
04-curl-returns-victim-data.png  [REQUIRED]
--------------------------------------------------------------------
How to capture:
  Terminal running:
      bash run.sh
  (or a manual curl with Authorization: Bearer <forgedToken>)
  Show the JSON body that the API returns. The response must contain
  orders / profile fields belonging to the VICTIM, not the attacker.

Must be visible:
  - The curl command or run.sh invocation
  - Response JSON with victim's username / orders

Caption:
  "Fig. 4 — The API returns the victim's orders in response to our
   forged token. No signature verification was performed by the
   Lambda — the swap was accepted."

--------------------------------------------------------------------
05-decoded-forged-payload.png    [OPTIONAL]
--------------------------------------------------------------------
How to capture:
  Paste the forged token into jwt.io (Debugger tab) or run
  `echo $PAYLOAD_B64 | base64 -d | jq .` and screenshot the decoded
  payload.

Must be visible:
  - "cognito:username": "<victim>"
  - "sub": "<victim-sub>"  (if you swapped it)
  - jwt.io's "Invalid Signature" warning is fine — that's the point

Caption:
  "Fig. 5 (optional) — Decoded forged payload. Even though jwt.io
   flags the signature as invalid, the production Lambda never checks
   it, so the token is accepted in practice."
